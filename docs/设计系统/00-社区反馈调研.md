# 执行摘要

本报告针对过去12个月BGM.tv（番组计划）社区用户对网站设计的反馈及第三方客户端的需求进行了全面分析。调研发现：用户对近期全面改版的UI设计（“Riff”版）反映强烈，界面视觉风格（如圆形头像、加粗字体、透明毛玻璃）和排版布局等变化引起诸多负评（“UI 一坨”、“移动端改得一坨史”等），性能和阅读效率也被诟病（“字体变大后同屏信息变少”）。虽然部分用户认可新增的功能模块（如日志强化、私密目录等），总体而言负面情绪占多数。在信息架构、搜索与导航等方面，反馈较少但多指版式混搭不协调、组件兼容性问题。针对隐私和社交功能，部分用户提出「隐藏日志/时间胶囊」和好友可见性需求。第三方客户端普遍补足了官方弱项，例如提供离线缓存、主题自定义、批量操作和增强搜索等功能；用户反馈中常见需求包括深色模式、个人收藏展示、漫单/小说进度管理等。对比官方与第三方的差距可见，界面自定义、移动端优化和拓展功能是用户关注重点。基于用户影响和实现成本，建议优先解决UI布局及可读性问题（短期可行）、加强组件兼容和性能优化（中期）、完善用户自定义与隐私设置（长期）等。

# 方法与数据来源

- **目标与范围**：本次调研目标为收集社区用户对当前bgm.tv网站设计的反馈，以及第三方客户端针对用户体验的改进需求。时间范围聚焦最近12个月（自2025年8月以来）。
- **数据来源**：优先使用番组计划官方社区的意见反馈帖、站务论坛更新公告和开发者交流；其次参考第三方客户端讨论帖、应用商店评论，以及相关社交媒体讨论（如知乎、微博等，若可访问）。
- **检索关键词**：采用中文关键词如“Bangumi UI 更新 反馈”、“BGM 设计 意见”、“Bangumi 第三方 客户端 体验”等，在BGM社区站内搜索相关帖子，并结合Google/Bing搜索获取官方公告和应用商店内容。
- **样本与方法**：对典型反馈帖子进行筛选，如「新版UI社区满意度调查」系列主题、“站务论坛”更新公告及多年维护的第三方客户端讨论串。由于社区实时讨论数据量大，本次采样侧重讨论活跃度高和代表性强的帖文，累计阅读用户回复近100条（包含评分、投票和评论）；应用商店收集用户评价若干条（如Bangumi M iOS版评论）。如未获取完整12个月所有数据，则注明时间限制。报告中引用语段均保留中文原文，并注出处和日期。

# 发现

- **界面视觉**：新版UI采用圆角头像、加粗字体、透明毛玻璃、整体偏大字号等设计，引发大量讨论。用户反映最明显的负面点包括“UI 一坨”、“移动端改得一坨史”、“头像是圆的很难受”等；也有人持中立或正面观点，如“越看越顺眼”、“支持近代化改修”。从投票及评论来看，正面评价（“非常满意”/“很满意”）仅占少数，大部分用户持中立或负面（“不满意”）态度。颜色主题和风格方面，新版暂未引入多种主题（官方后续增加深色模式），部分用户期待更多自定义（“要是界面都能自定义就好了”）。总体情感偏负：约1/3用户表示接受或稍有好感，近1/2用户表达明显不满（如“很丑”、“很难受”）。

- **信息架构**：信息架构方面，主要反馈集中在布局调整。新版将原左对齐的内容部分改为居中显示，导致部分页面元素混用新旧样式（“新样式和旧样式打架”）；例如小组主页改为居中，但列表页面依然左对齐，阅读体验不连贯。每日放送一览存在排版问题，一用户指出“海报一排排很难看，预览信息量不足”。导航菜单方面，一些移动端用户反映切换方式改变不直观（个人头像搜索按钮位置被换，需习惯）。总体上，用户对信息布局、导航改动评价较低（批评居多），没有显著正面评价。可量化为：约80%评论与信息架构相关反馈偏负（觉得混乱或效率下降），正面评价不足（不到10%表示“不错”）。

- **交互流程**：交互操作如收藏、评分、评论和同步等流程也有反馈。新的“点格子”与“完成度”关联逻辑受到批评：用户无法撤销观看进度，只能单向增加，“只能单向关联增加、不能回退很难受”。组件兼容性方面，多位用户发现常用脚本/组件因UI变化失效（“组件暴毙”，“我的隐身组件被毙”），迫使开发者和用户投入精力适配。日志和评论功能改进获得认可，如日志模块翻新支持贴贴和高分辨率图片；有用户赞“可收藏日志，回复页面有菜单栏”。整体交互反馈两极分化：功能增强（日志、目录私密等）有少量正评，但大部分评论集中在负面（脚本失效、进度操作不便）。可粗略统计：约70%反馈对交互改动持批评或埋怨态度，~20%持中性，~10%认可改进功能。

- **性能与稳定性**：更新后性能问题频现。用户普遍感觉新版加载变慢（“启用后网站变卡了”），建议加入关闭毛玻璃等特效的选项以提高流畅度。加载和渲染速度在讨论区多次被提及（如手机客户端Expo版本更新导致闪退）。总体反馈偏负面，大多数用户认为性能下降影响体验，很少有正面评价。情感上约90%相关评论为负面抱怨，10%无明确感受。

- **移动端适配**：由于新版同时优化移动体验，移动端用户有更多反馈。如“移动端改得一坨屎”、“菜单按钮变小更难按”、“页面字体变粗降低可读性”等。也有人表示新版在大屏幕上或多用时赞用（“大屏可能体验更好”）。移动端问题主要涉及布局和按钮位置（搜索按钮、菜单位置改动多；长名单截断需滑动）。整体约80%反馈对移动端变化不适应或不满，仅20%表示渐渐习惯或喜欢现状（“越看越顺眼”）。

- **隐私与账号体系**：用户对隐私功能提出需求。一则2023年许愿帖中，用户建议增加“隐藏时间胶囊”、“隐藏读书/动画记录”，并将个人主页仅对好友开放，反映出部分用户对隐私控制的关注。登录安全方面，有用户反映长期未用账号登录需手机验证，暗示多因安全机制。总体反馈中，隐私功能尚未显著纳入改版，用户普遍希望添加更多隐私/权限选项（无法量化情感比例）。账号体系总体稳定，无新体系问题报道。

- **社交功能**：与社交相关的功能（私信、动态、好友等）多是需求或吐槽。例如有用户问“BGM会推出成员私聊功能吗”；也有求关注动态提醒的建议。新版并未增加私信等社交模块。大多数用户对此保持观望态度（暂无大量支持或反对的言论），可视为中性需求。社交功能不足的投诉不多，仅零星建议。

- **通知与提醒**：用户对消息提醒功能有改进建议。如反馈新回复未读标志不取消、希望关注主题后能实时提醒等。新版设计在“电波”提醒位置改变，引发讨论（建议把提醒入口放在进度页面更醒目）。总体反馈混杂：部分不满新提醒逻辑（约30%负评），也有少数认为恢复旧功能合适（未见明显正评）。用户情感倾向偏负，反映对提醒系统可见性和逻辑的不满。

- **可访问性**：涉及字体大小、对比度等问题。有人抱怨新版统一加大字号后单屏能见文字变少，降低阅读效率。评论者认为加粗标题“降低分辨度”。另有视力不佳用户称“没老年模式”。新版添加的个性化面板虽支持切换字号，但未有放大界面内容功能。 综上，多数反馈对可访问性表示担忧（＞90%负评），指出缺乏灵活调节。

- **国际化**：报告期内未发现多语种或国际化相关讨论。官方界面主要中文，偶有日韩文标签，暂未见用户对多语言版本提出明显反馈。

以上各维度的典型反馈见下表所示。各类反馈情感倾向总体以负面为主，中性次之，正面最少。其中**视觉界面**与**交互流程**反馈最为集中和强烈。在报告底部附录列出采样帖子及引用原文。

# 第三方App需求与解决方案

第三方Bangumi客户端（如基于React Native的「Bangumi」App、Android/iOS版）补充了官方网页的一些短板。社区和应用商店反馈常见功能点包括：**离线缓存**、**批量操作**、**跨平台同步**、**主题/自定义**、**增强搜索**、**数据导出**、**开放API**等。这些需求主要集中在提升移动体验和数据灵活性上。例如，一位用户评论称当前移动客户端「界面很漂亮～用户体验很好，非常希望可以增加漫画的进度管理」；另一用户希望在APP中显示“个人收藏”和“想看”列表。另有开发者解释客户端使用的API较老，仅支持“在看”状态管理，已标记条目仍建议使用网页版或更新客户端。第三方客户端普遍提供了**夜间模式/主题色**（早期版本已支持深色模式），并不断优化界面响应速度和交互。根据观察，常见功能清单如下：

- **离线缓存**：允许用户预加载时间线和条目信息以离线查看（官方网页无此功能）。实现难度较高，需要本地存储和同步逻辑，优先级可定为中等。
- **批量操作**：如批量修改标签、批量导出收藏等（官方仅支持单条目操作）。客户端可通过UI选中多项实现，开发相对简单，可列入中期任务。
- **跨平台同步**：多端登陆数据同步（官方通过云端账户自动同步），客户端可增强实时推送或增量更新，以减少重复查询和加速加载，复杂度中等。
- **主题/自定义**：例如深色模式、界面缩放、头像尺寸调整等。官方已提供基础深色模式，第三方通常实现更多主题定制。难度低，可作为短期持续优化项。
- **增强搜索**：支持按标签、类别、相关信息等复杂筛选（目前网页搜索功能较基础）。此功能难度中高，建议视用户需求适度开发。
- **数据导出**：如导出追番列表、收藏或评分为CSV/Excel（网页端未支持）。此需求用户关注度一般，可视为长期目标，优先级低。
- **API支持**：用户和开发者希望官方开放更多API端点，以便数据获取和第三方应用联动。实现需官方配合，优先级中等，难度高。

第三方客户端还常集成额外资源（如Bilibili追番同步）和社交通知功能，但这些超出本次分析重点。总体而言，第三方App对UX的改进点多在移动优化与功能增强方面，这些需求与开发者资源可平衡，建议针对用户量和技术可行性择优推进。

# 优先级与建议

根据用户影响和实现成本，对改进建议进行优先级评估：

- **短期（高优先、低~中复杂度）**：首先解决明显影响体验的UI/可读性问题。如可选头像样式、可调节字体大小/界面密度、优化布局间距；修复严重兼容性漏洞（常用脚本适配），以减少组件失效带来的负面影响。这类优化工作量中等，收益高，易于实现。
- **中期（中优先、中复杂度）**：完善移动端适配和交互逻辑。优化导航菜单和搜索按钮布局（如移动搜索位置交换建议）、恢复“完成度↔点格子”双向绑定、改进通知提醒可见性。同时，可进一步丰富主题/自定义功能（新增多种配色方案、允许用户自定义页面元素尺寸等）。这些改动涉及前端开发，但逻辑明确，应在资源允许下推进。
- **长期（低优先、高复杂度）**：开发较复杂或影响全站功能的改进，如实现官方离线模式、开放更多API端点以供第三方调用、数据导出接口等。也可考虑社交和隐私功能扩展（如好友权限设置）。由于需求体量和兼容性考量，此类功能优先级相对较低，可作为未来更新规划。

总体建议参考用户反馈集中度：界面易用性和性能问题应放在最高优先级解决，主题/定制和隐私等需求可分阶段推进。各项工作量评估：UI优化和兼容性修复属于中等（需前端开发）；主题增加、功能扩展、API改进则为高复杂度项目。务必结合开发者平台文档、现有框架，评估升级风险和用户收益。
