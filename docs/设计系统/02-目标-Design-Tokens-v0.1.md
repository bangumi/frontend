# Bangumi 定制设计系统：目标 Design Tokens v0.1（提案）

- 状态：**v0.1 已确认，待试点验证**。本文件是新系统的目标规范，不是对旧站 CSS 的转录。
- 前置决策：[01-改版方向 v0.1](01-改版方向-v0.1.md)。
- 证据基线：[基础组件与共享 Tokens](../审计/基础组件与共享Tokens.md)。
- 适用范围：React + SSR 的网页端；亮色与深色主题；现代浏览器。移动端、登录态和完整表单流程尚未审计，相关 token 先定义通用语义，不预设具体业务流程。

## 1. 目标与使用规则

目标是在保留 Bangumi「高密度、文本与链接驱动」特征的前提下，建立可跨页面、跨主题和跨端复用的视觉基础。

1. **先用语义 token，后用组件 token。** 页面与组件不得直接写 `#hex`、裸字号或任意阴影；应引用本文件的语义值。
2. **旧站数值只作对照。** 例如旧站 12px 正文、粉色当前态、直角列表，均不自动成为新系统标准。
3. **密度是可调规则，不是缩小文字。** 正文以 14px 为默认下限；高密度由行高、间距和信息分组控制。
4. **主题切换只替换语义颜色。** 组件不应知道自己处于亮色还是深色主题。
5. **v0.1 的颜色是工作候选。** 在试点页面以真实内容和 WCAG 对比度复核后，再冻结为 v1。

### 命名约定

- `ref-*`：原始色阶，仅供 token 定义使用，不在业务组件中直接引用。
- `color-*`：跨组件的语义颜色。
- `component-*`：组件私有 token，后续组件文档定义。
- CSS 建议以 `--bg-canvas`、`--text-primary` 这类语义变量落地；设计工具可保持同名分组。

## 3. 排印

### 3.1 字体族

不要求首屏下载 Web Font。v0.1 采用系统字体以保证 SSR 首次渲染、性能和 CJK 字符覆盖。后续仅在系统字体无法满足明确设计需求时评估开放许可的 Web Font；届时须验证中文、日文、英文、数字与罕见字符样本，并采用字体度量覆盖、合理回退与 `font-display` 策略控制布局抖动。

```css
--font-sans:
  'SF Pro SC', 'PingFang SC', 'Hiragino Sans GB', 'Microsoft YaHei UI', 'Noto Sans CJK SC',
  'Noto Sans JP', 'Segoe UI', Arial, sans-serif;
--font-mono: 'SFMono-Regular', Consolas, 'Liberation Mono', monospace;
```

| token                | 字号 / 行高 | 字重 | 默认用途                      |
| -------------------- | ----------- | ---- | ----------------------------- |
| `text-meta`          | 12px / 18px | 400  | 时间、票数、极短辅助信息      |
| `text-body-sm`       | 13px / 20px | 400  | 紧凑列表、表格、定义列表      |
| `text-body`          | 14px / 22px | 400  | 默认正文、评论摘要、表单      |
| `text-body-lg`       | 16px / 26px | 400  | 长文阅读、重要评论正文        |
| `text-label`         | 14px / 20px | 500  | 控件标签、页签、列表标题      |
| `text-title-sm`      | 16px / 24px | 600  | 带摘要/作者的独立内容单元标题 |
| `text-section-title` | 18px / 26px | 300  | 详情页、资料页的内容分区标题  |
| `text-title`         | 20px / 28px | 650  | 页面/条目标题                 |
| `text-display`       | 28px / 36px | 650  | 仅用于少数独立页面标题        |

- 数字、评分和日期默认使用等宽数字特性：`font-variant-numeric: tabular-nums;`；文章正文不强制。
- 正文段落长度宜为 45–75 个拉丁字符等效宽度；中文长文阅读列建议不超过约 720px。
- 不以全大写作为中文环境的层级手段；英文缩写保留其原始语义。

## 4. 空间、尺寸与形状

### 4.1 空间刻度

采用 4px 基准，既能保留旧站紧凑性，也方便触控与响应式扩展。

| token     | 值   | 典型用途                   |
| --------- | ---- | -------------------------- |
| `space-1` | 4px  | 图标与文字间隔、极紧凑内距 |
| `space-2` | 8px  | 行内控件、紧凑列表         |
| `space-3` | 12px | 默认分组内距               |
| `space-4` | 16px | 分区内距、标准间隔         |
| `space-5` | 20px | 紧凑内容块之间             |
| `space-6` | 24px | 连续内容流中的主区块、列距 |
| `space-7` | 32px | 页面级分隔                 |
| `space-8` | 48px | 罕用的大留白               |

### 4.1.1 间距职责与语义层

空间 token 分为三个层次，页面与组件必须先判断空间的**职责**，再选择数值：

1. **基础刻度（`space-*`）**：唯一的像素来源，用于局部、一次性的尺寸选择；不得新增任意值替代刻度。
2. **布局角色（建议以语义 spacing token 或 Stack/Grid primitive 暴露）**：`layout.inline`、`layout.compact`、`layout.group`、`layout.section`、`layout.page`，用于跨页面稳定的兄弟元素间距和容器 gutter。
3. **组件私有角色（`component.*`）**：仅当某组件有稳定、可复用的内部节奏时定义，例如 `component.list.rowBlock`、`component.media.frame`、`component.panel.padding`；不为单个页面的偶然距离创建 token。

#### 使用规则

- **同一父容器的兄弟关系优先使用 `gap`。** 栅格列、区块堆栈、标题与操作组、行内图文和媒体轨均由父容器声明 `gap`。子组件不得以根节点的 `margin-bottom` 猜测下一个兄弟是谁。
- **`padding` 仅定义元素自身的内部边界。** 页面容器 gutter、按钮/输入框/可点击行的命中区、带背景/边框/分组表面的内容内距可使用 padding。透明且没有独立边界的普通内容区块不得为了制造区隔增加 padding。
- **`margin` 是例外，不是默认布局机制。** 仅用于跨布局边界的光学校正、原生元素默认样式复位、排版中的段落规则，或暂时无法改造的兼容层。相邻区块的标准距离必须回收到共同父容器的 gap。
- **一个距离只能有一个所有者。** 父 stack/grid 已提供外部 gap 时，子组件根节点不再提供同一方向的外边距；组件有 padding 时，不能再以父级 padding 重复制造同一层边缘。

#### 建议的布局角色映射

| 角色             | 建议基础刻度                             | 适用范围                         | 禁止用于                   |
| ---------------- | ---------------------------------------- | -------------------------------- | -------------------------- |
| `layout.inline`  | `space-1`（4px）                         | 图标与文字、紧凑行内项           | 页面或区块分隔             |
| `layout.compact` | `space-2`（8px）                         | 数据行内部列、紧凑控件组         | 独立内容区块               |
| `layout.group`   | `space-4`（16px）                        | 一个区块内的标题、内容、元数据组 | 三栏列距                   |
| `layout.section` | `space-6`（24px）                        | 连续内容流中的相邻主区块         | 控件内距                   |
| `layout.page`    | `space-7`（32px）                        | 页面级章节或明确阅读阶段的分隔   | 普通详情页的每一个 section |
| `layout.gutter`  | 响应式 `space-4` / `space-6` / `space-7` | 页面容器至视口边缘               | 单个面板内容内距           |

| 组件角色                       | 基础刻度                  | 适用范围                                 | 约束                                                     |
| ------------------------------ | ------------------------- | ---------------------------------------- | -------------------------------------------------------- |
| `component.list.rowBlock`      | `space-2`（8px）          | 连续事实、数据与列表行的上下内距         | 不添加水平 padding，保持与区块边缘对齐                   |
| `component.list.rowBlockDense` | `space-1`（4px）          | Wiki 事实表等高密度连续行的上下内距      | 与 `component.list.divider` 分割线配套；不用于触控操作行 |
| `component.list.divider`       | 1px solid `border-subtle` | 连续数据、事实与列表行之间的低强调分隔线 | 宽度、线型与亮/暗主题颜色作为一个 token 使用             |
| `component.media.frame`        | `space-1`（4px）          | 有边框的封面或媒体框内衬                 | 外部距离由媒体轨或父级 stack 的 gap 决定                 |

条目详情试点已在 `theme/semantic-tokens.ts` 将本表实现为 `spacing.layout.*`。语义 token 是布局角色的唯一入口；基础 `space-*` 仍是其像素来源。此表已与当前实现对齐；后续跨页面验证可以调整语义角色到基础刻度的映射，但不得让文档与代码各自维护数值。

## 5. 布局与响应式

断点按内容失效点而非设备型号使用。页面必须先在窄宽度建立单列可用结构，再增加并列信息。

| token               | 值                             | 默认布局意图                                                    |
| ------------------- | ------------------------------ | --------------------------------------------------------------- |
| `breakpoint-sm`     | 480px                          | 小屏手机；最紧凑但不缩小正文                                    |
| `breakpoint-md`     | 768px                          | 平板；可出现局部双列                                            |
| `breakpoint-lg`     | 1024px                         | 笔记本；可恢复资料侧轨                                          |
| `breakpoint-xl`     | 1280px                         | 常规桌面；完整页面壳层                                          |
| `breakpoint-2xl`    | 1600px                         | 宽屏；增加有效并列空间，不拉长阅读列                            |
| `container-page`    | 1264px                         | `PageContainer` 的外框上限，容纳 1200px 内容区和桌面双侧 gutter |
| `container-reading` | min(100% - 32px, 720px)        | 日志、长评等连续阅读                                            |
| `container-content` | min(100% - 2 × gutter, 1200px) | 条目、目录、用户页的默认内容壳层                                |
| `container-wide`    | min(100% - 48px, 1440px)       | 宽屏比较、编辑、复杂表格；仅明确需要时使用                      |

`PageContainer` 是默认页面 gutter 的唯一所有者：小于 `768px` 时为 16px，`768px` 以上为 24px，`1280px` 以上为 32px。它采用 `border-box`，因此有效内容宽度固定为 $\min(\text{viewport width} - 2 \times \text{gutter}, 1200px)$；桌面端外框上限为 $1200 + 2 \times 32 = 1264px$。页面根节点不得再声明横向 padding。条目详情的侧轨在内容无法容纳时下移或折叠，不能制造横向页面滚动。

## 6. 动效与可访问性基础

| token           | 候选值                       | 用途                  |
| --------------- | ---------------------------- | --------------------- |
| `motion-fast`   | 120ms                        | hover、颜色、焦点反馈 |
| `motion-normal` | 200ms                        | 展开、切换、轻量浮层  |
| `motion-slow`   | 320ms                        | 仅用于明显的空间重排  |
| `ease-standard` | `cubic-bezier(0.2, 0, 0, 1)` | 默认过渡曲线          |

- 仅为状态变化与空间关系提供动效；不使用自动播放的装饰动画。
- `prefers-reduced-motion: reduce` 下，持续/位移动效应关闭，过渡缩至不可感知的最短时间。
- 所有可操作组件同时具备默认、hover（如适用）、focus-visible、active、disabled、loading（如适用）状态；hover 永远不是唯一反馈。
- 触摸主要操作的实际命中区域最低 44 × 44px；密集桌面控件可视觉上较小，但移动端必须扩展热区或换用更大规格。
- 焦点顺序遵循 DOM 阅读顺序；不得因视觉重排破坏键盘流程。

## 7. v0.1 明确不做的事

- 不把所有内容改为 Card，不引入全局玻璃、渐变或大阴影语言。
- 不定义尚无业务证据的复杂业务状态（例如收藏状态机、评分流程、通知规则）。它们在登录态审计后进入组件层。
- 不为单页特殊效果创建全局 token；例如角色横向轨、目录分段控件、评分图表仍属于页面/组件级变体。
- 不承诺令所有历史第三方样式无需适配。兼容策略需单独立项和评估。

## 8. 已确认的设计决策

| 决策     | 已确认规则                                                                                          | 对后续工作的影响                                                      |
| -------- | --------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| 默认密度 | **平衡**：14px 默认正文、42px 默认控件；紧凑数据行可使用 13px。                                     | 试点需同时验证信息扫描效率与 44px 移动触控热区。                      |
| 深色主题 | 与亮色主题**同等覆盖**。                                                                            | 每个组件交付、截图和对比度测试均须包含亮/暗两种主题。                 |
| 个性化   | v0.1 **仅提供亮/暗主题**，支持系统跟随与手动选择。                                                  | 不新增字号、密度、多皮肤等设置；语义 token 保留未来扩展空间。         |
| 字体交付 | **优先系统字体**。仅在系统字体无法满足明确需求时，评估开放许可 Web Font，并控制加载造成的布局抖动。 | Web Font 不进入当前关键路径；组件测试覆盖主要系统与中日英混排。       |
| 品牌粉   | **维持品牌色**，主要位于按钮、导航与当前/选中指示，较少作为纯文字。                                 | 普通链接保持蓝色；当前态以指示器/填充等多重线索表达，不只改文字颜色。 |

## 9. 冻结前的验证清单

1. 将 token 应用于“条目首页”试点的桌面、768px 与 375px 视图，不先做全站替换。
