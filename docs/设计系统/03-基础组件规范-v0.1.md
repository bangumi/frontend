# Bangumi 定制设计系统：基础组件规范 v0.1（提案）

- 状态：**提案，待审核**。
- 依赖：[改版方向 v0.1](01-改版方向-v0.1.md)、[目标 Design Tokens v0.1](02-目标-Design-Tokens-v0.1.md)。
- 现状证据：[基础组件与共享 Tokens](../审计/基础组件与共享Tokens.md)。
- 范围：第一批跨页面基础组件。业务组合（评分、收藏、评论、讨论、章节等）在本批组件获批后另行规范。

## 1. 本批目标与通用规则

本批首先统一页面中出现频率最高、最影响阅读效率的交互语言：链接、按钮、导航与页签、连续列表、分页、输入控件。它们应保持克制、高密度、键盘可用和亮/暗主题一致，而非套用营销式组件库的默认外观。

### 所有交互组件必须满足

1. 有语义 HTML 优先：导航链接使用 `<a>`，触发页面内动作使用 `<button>`，输入使用原生表单元素。
2. 有可见的 `:focus-visible` 状态，使用 `focus-ring` token；鼠标点击后不强加焦点环。
3. 状态不只由颜色表达。禁用、当前、错误、加载等至少有文本、图标、位置或可操作性变化之一。
4. 控件视觉尺寸可紧凑，但触屏热区最低为 44 × 44px；在密集桌面表格中可经测试使用例外。
5. 不把外观相同的元素误做成同一组件：链接负责导航，按钮负责动作，页签负责同页/同上下文内容切换。

### 状态缩写

以下规格中的状态均以 `default / hover / focus-visible / active / disabled / loading` 表示；不适用的状态会明确写出。所有颜色、空间、半径均引用 `02` 中的 token。

## 2. Link

### 目的

用于页面跳转、锚点跳转或打开外部资源。Bangumi 的信息架构以链接为核心，因此链接需要易发现但不能让整页密集文本变成蓝色噪声。

### 变体与用法

| 变体     | 何时使用                          | 外观                                              | 不可用于                   |
| -------- | --------------------------------- | ------------------------------------------------- | -------------------------- |
| `inline` | 正文、摘要、元数据中的可跳转文字  | `color-link`；与正文同字号                        | 触发收藏、删除、展开等动作 |
| `title`  | 列表标题、条目名、话题标题        | `color-link`，继承标题排印                        | 代替页面 H1                |
| `subtle` | 次级导航、元信息链接              | `text-secondary`；hover/focus 切换为 `color-link` | 关键跳转入口               |
| `nav`    | 全局/局部导航，由 Navigation 承载 | 由导航组件规定当前态                              | 普通正文链接               |
| `danger` | 跳往不可逆操作的确认页或危险资源  | `color-danger`，须有明确文案                      | 直接执行删除动作           |

### 状态与行为

| 状态                  | 规则                                                                                             |
| --------------------- | ------------------------------------------------------------------------------------------------ |
| default               | `inline` 与 `title` 默认可识别为链接；正文中不依赖只有颜色，推荐在 hover/focus 下加 1px 下划线。 |
| hover / focus-visible | 使用 `color-link-hover`，并显示下划线；焦点环不被下划线取代。                                    |
| active                | 保持可读对比度，允许短暂使用更深色；不改变布局。                                                 |
| visited               | v0.1 不作跨站历史的显著颜色区分，避免目录和讨论列表出现信息噪声；可在后续可用性验证后增补。      |
| disabled              | 链接原则上不应禁用；没有目的地时改为文本或按钮的禁用态。                                         |

### 内容与无障碍

- 链接文本应说明目的地，避免孤立的“这里”“更多”。图标链接必须有可访问名称。
- 新窗口仅用于确有必要的外部跳转，并以图标/文案提示；不要让普通站内链接任意新开窗口。
- 不把整张内容行都做成链接；行内有多个目标时保留可逐项操作的链接。

## 3. Button

### 目的

按钮只执行动作：提交、保存、回复、展开、确认收藏或打开菜单。旧站并未提供充分的通用 Button 样本，因此此处是基于已确认方向的**新系统提案**，须在登录态与发布流程审计后扩充。

### 尺寸与变体

| 变体        | 视觉规则                                                   | 典型用途                                 |
| ----------- | ---------------------------------------------------------- | ---------------------------------------- |
| `primary`   | `bg: color-accent`、`text: color-on-accent`、`radius-sm`   | 每个局部任务的首要提交：发表、保存、确认 |
| `secondary` | `bg: bg-muted`、`text: text-primary`、`1px border-default` | 次级动作、筛选确认                       |
| `tertiary`  | 透明背景、`text: color-link`                               | 与正文相邻的低强调动作                   |
| `danger`    | `bg: color-danger`、白色/深色前景；仅确认后执行            | 删除、撤销不可恢复内容                   |
| `icon`      | 无文字时须有 tooltip 与可访问名称；默认透明或 `bg-muted`   | 搜索、关闭、更多菜单                     |

| 尺寸 | 高度 | 水平内距 | 默认场景                                 |
| ---- | ---- | -------- | ---------------------------------------- |
| `sm` | 32px | 12px     | 桌面紧凑工具栏；移动端扩大热区           |
| `md` | 42px | 16px     | 默认表单与操作；与现有主按钮实测高度对齐 |
| `lg` | 48px | 20px     | 移动端主操作、重要搜索                   |

### 状态与约束

- `primary` 在一个连续任务区通常只有一个；不能把所有可点击项设计成粉色按钮。
- hover 可改变背景至对应深色阶；active 可轻微降低亮度，不使用位移造成布局跳动。
- disabled：降低对比和可操作性，移除鼠标指针暗示；须说明不可用原因或让原因在上下文可见。
- loading：保留按钮宽度、阻止重复提交、显示 spinner 与“处理中”可访问文案；不可只旋转图标而没有状态通知。
- 破坏性操作不以红色按钮作为唯一保护；应结合确认、撤销或明确的后果说明，具体策略待业务审计。

## 4. Navigation 与 Tabs

### 4.1 Navigation

用于全站分类、账户入口和跨页面路径。视觉上是“前往别处”，不与页面内筛选或按钮混同。

| 类型                 | 结构与规则                                                                                                           | 响应式规则                                                  |
| -------------------- | -------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------- |
| `masthead`           | 高度建议 53–56px；品牌入口、主分类、搜索、账户工具分组排列。当前分类可用粉色填充或粉色标识，但不将所有导航项胶囊化。 | 小屏优先保留品牌、搜索、账户/菜单；其余项收纳入可访问菜单。 |
| `section-nav`        | 位于页面标题或内容前；文字链接为主，使用间距和当前指示建立层级。                                                     | 项目过多时允许横向滚动，但须显示可滚动提示并支持键盘。      |
| `breadcrumb`（可选） | 仅在深层路径确能减少迷失时加入；使用 `text-secondary` 与明确分隔符。                                                 | 可截断中间层级，保留首层和当前页。                          |

当前项使用 `aria-current="page"`；粉色仅作为补充，建议以底部 2px 指示线、填充背景或字体权重共同表达。当前项不可仍是指向本页的无意义链接。

### 4.2 Tabs

用于不离开当前上下文的并列内容视图，例如条目“概览 / 章节 / 讨论”。若切换会改变 URL 且可独立打开，应优先使用 `section-nav` 链接而非 ARIA Tabs。

| 项目          | 规格                                                                                                              |
| ------------- | ----------------------------------------------------------------------------------------------------------------- |
| 视觉          | 默认 `text-secondary`；当前项使用 `text-primary` + `color-accent` 的 2px 底部指示线。不得仅以粉色文字判断当前态。 |
| 尺寸          | 默认高度 40px，水平内距 `space-3`；紧凑变体高 32px，仅用于用户状态等高密度上下文。                                |
| 容器          | 透明或 `bg-subtle` 的导航带；内容列表不要套入泛化卡片。                                                           |
| hover / focus | hover 可提升至 `text-primary`；focus-visible 显示统一焦点环。                                                     |
| 禁用          | 少用；不可用内容应显示原因或不展示该项。                                                                          |
| 溢出          | 不换行造成二三行页签；小屏可横向滚动，当前项切换后须滚动至可见位置。                                              |

如采用 ARIA tablist 模式，必须实现左右方向键、Home/End 和关联的 tabpanel；否则使用语义 `<nav>` + 链接，避免伪 Tabs。

## 5. Continuous List 与数据行

### 目的

列表行是目录、收藏、人物作品、讨论和检索结果的核心骨架。默认是连续信息流，不是卡片瀑布流。

### 结构

- 行内可包含媒体缩略图/封面、主标题、原名/说明、评分/进度/时间等元数据，以及有限的行级动作。
- 主信息与操作在窄屏优先保留；次级元数据可换行、折叠或移至详情，不能压成不可读的省略号墙。
- 标准行内距为 `space-2` 垂直、`space-2` 至 `space-3` 水平；内容丰富时升为 `space-3`。

### 视觉与状态

| 状态         | 规则                                                                                   |
| ------------ | -------------------------------------------------------------------------------------- |
| default      | 透明底或透明/`bg-subtle` 的交替行，底部 `border-subtle`；`radius-none`。               |
| hover        | 仅当行整体可激活时出现轻微 `bg-subtle`；多链接行不得使整行 hover 与内部目标竞争。      |
| selected     | `color-accent-subtle` + 非颜色线索（勾选、左边标识或明确状态）；用于批量操作前的选择。 |
| focus-within | 当行内某操作聚焦时不遮挡该元素的焦点环；可用细边界辅助定位。                           |
| loading      | 使用与真实行相同高度的 skeleton，避免内容加载后跳动；须尊重减少动态效果偏好。          |
| empty        | 说明“没有结果”的原因与下一步（清除筛选、调整关键词），不只显示空白。                   |

### 密度边界

- `dense`：13px/20px，适用于目录、收藏、讨论表；行必须能容纳 44px 的移动热区或改为分层布局。
- `default`：14px/22px，适用于搜索、关系内容和常规列表。
- 图片不等于 Card：封面自身可有 `radius-sm`，但列表容器默认无大圆角/阴影。

## 6. Pagination

### 目的

用于稳定、可索引的长列表分页。无限滚动若让用户失去位置、无法回到特定页或影响 SEO，不作为默认替代。

| 项目 | 规格                                                                                                           |
| ---- | -------------------------------------------------------------------------------------------------------------- |
| 结构 | 上一页、页码、下一页；页数过多时使用省略号，省略号不是可点击控件。                                             |
| 外观 | 非当前页为 `bg-muted` + `text-primary`；当前页为 `color-accent` 填充 + `color-on-accent`；使用 `radius-pill`。 |
| 尺寸 | 默认 `sm`，最小视觉高度 32px，页码间距 `space-1`；触屏热区不低于 44px。                                        |
| a11y | 外层 `<nav aria-label="分页">`；当前页添加 `aria-current="page"`；上一/下一页有完整可访问名称。                |
| 禁用 | 首/尾页没有前/后页时，显示不可操作文本或禁用按钮，不能保留可点击空链接。                                       |

在长页面底部应紧随列表出现；需要时可在顶部加简化分页，避免用户先滚到底才能切页。

## 7. Text Input、Select、Checkbox 与 Radio

### 目的与已知边界

审计仅证实旧站顶栏搜索的原生输入与选择器，未覆盖登录、发表、编辑和设置表单。v0.1 因此先定义可访问的通用表单基础；字段组合、校验时机和业务文案需在登录态审计后制定。

### 7.1 Text Input 与 Textarea

| 项目                | 规格                                                                                                       |
| ------------------- | ---------------------------------------------------------------------------------------------------------- |
| 默认                | 42px 高（多行输入除外）、`bg-inset`、`1px border-default`、`radius-sm`、左右 `space-3` 内距、`text-body`。 |
| hover               | 边框提升为 `border-strong`。                                                                               |
| focus-visible       | 保留默认边框，同时显示 `focus-ring`；不只依赖变色。                                                        |
| disabled / readonly | 视觉明确降低；readonly 仍允许选择文本，disabled 不可聚焦。                                                 |
| error               | `border: color-danger`，紧邻字段显示具体错误文案和图标；`aria-describedby` 关联帮助/错误信息。             |
| textarea            | 默认可垂直缩放；发布类长文本另在业务组件定义最小高度、预览和草稿逻辑。                                     |

标签必须始终可见，placeholder 只提供示例而不替代标签。搜索输入可使用图标，但图标不能遮挡输入文字或成为唯一提交方式。

### 7.2 Select

- 默认使用原生 `<select>`，以获得可靠的键盘、辅助技术和移动端体验；不因视觉统一仓促自定义。
- 高度 40px，和 Input 一致；较窄的顶栏搜索组合可使用 32px 紧凑变体。
- 仅当原生控件无法完成明确需求（例如可搜索多选）时，新增专用组合框组件，并单独完成键盘与屏幕阅读器规范。

### 7.3 Checkbox 与 Radio

| 组件     | 使用场景                               | 规则                                                     |
| -------- | -------------------------------------- | -------------------------------------------------------- |
| Checkbox | 独立的开关型选择、可多选筛选、批量选择 | 标签点击可切换；不确定态只用于部分选中集合。             |
| Radio    | 互斥选项                               | 同组有可见组标题；不允许取消后无选择，除非业务明确允许。 |

两者默认不做品牌化复杂重绘；若自定义外观，必须保留原生语义、键盘操作和 44px 标签热区。选中状态可用粉色，但仍需勾选/实心圆等形状线索。

## 8. 组件组合的禁止事项

1. 不用 Button 模拟普通页面跳转，也不把动作伪装为链接。
2. 不在每个标题、列表、侧栏外包一层有阴影的大圆角 Card。
3. 不将移动端的导航、页签或分页压缩到小于可可靠触控的目标。
4. 不让 hover、颜色或 tooltip 成为理解与完成关键任务的唯一手段。
5. 不在组件尚未审计的情况下，擅自定义收藏、评分、发布或删除的完整业务状态机。

## 9. 试点与审核项

将本规范应用于“条目首页”试点时，至少验证：

1. Masthead、条目页 section-nav 与页面内 Tabs 是否清楚地区分“跳转”和“切换”。
2. 角色、关联条目、评论、讨论与吐槽等连续内容是否仍保持紧凑可扫描，而非变成卡片墙。
3. 375px、768px、1280px、1600px 下，导航/页签/分页是否无意外页面横向滚动。
4. 亮/暗主题的链接、当前态、重点按钮、输入错误与焦点环是否均通过对比度和键盘测试。
5. 用真实中日英混排、长标题、长用户名和空/加载状态审查排印与布局。

## 10. 待审核决策

本文件的基础方向足够进入试点，但以下两项需要你在组件视觉稿前确认：

| 决策                    | 当前提案                                                   | 影响                                                         |
| ----------------------- | ---------------------------------------------------------- | ------------------------------------------------------------ |
| 当前导航/页签的粉色表现 | 粉色 2px 指示线或有限填充，当前文字主要保持 `text-primary` | 决定全站当前态的一致视觉；避免纯粉文字在密集导航中过量出现。 |
| 主按钮密度              | 默认 40px，高密度工具栏 32px（移动端维持 44px 热区）       | 影响发布、收藏、筛选和编辑工具栏的视觉节奏。                 |

审核后，本批组件可进入条目首页试点；下一份文档应为 `04-条目详情页组合规范-v0.1`，将基础组件组织为 Hero、信息侧轨、评分、角色轨、关联内容与社区内容等页面结构。
