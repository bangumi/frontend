# Bangumi 定制设计系统：改版方向 v0.1

- 状态：已确认方向；仍不是最终视觉规范。
- 依据：现有未登录桌面端 UI Audit，尤其是[基础组件与共享 Tokens](../审计/基础组件与共享Tokens.md)与[条目首页](../审计/条目/首页-SHIROBAKO.md)。
- 已知边界：移动端、登录态、编辑/发布流程及多数表单状态尚未审计；本文件不对它们作既成结论。

## 一句话方向

将 Bangumi 渐进式现代化为**安静、紧凑、可信赖的兴趣资料库与社区**：保留 Wiki 式内容优先、高信息密度与编辑效率，提升阅读层级、宽屏和跨端可用性、交互反馈、一致性与无障碍，而不将它改造成大图驱动、强营销感的流媒体产品。

本项目不是推倒重来。新旧界面的切换、核心任务路径和信息组织应尽量延续现有用户习惯；创新应优先解决明确的可用性问题，并通过页面试点验证。

## 设计要解决的问题

1. 让用户更快分辨「这是资料、讨论、进度还是个人记录」，减少密集文本中的定位成本。
2. 让长页面、列表、目录和讨论在窄屏上仍可阅读、筛选与操作。
3. 让相同语义在不同页面有一致的外观和状态，降低学习与实现成本。
4. 提升文字可读性、触控目标、焦点可见性和状态反馈，同时不牺牲老用户熟悉的信息密度与编辑效率。

## 核心设计原则

### 1. 内容密度可控，不以留白换取“现代感”

Bangumi 的价值来自条目事实、评分、进度、关联关系和社区文本的并置。默认界面应保持高密度，但用排印、分组、留白节奏和渐进披露来降低认知负担；不把连续列表普遍替换为大卡片网格。

**意味着：** 列表行、定义列表、表格和讨论串是一级组件；卡片仅用于确有独立边界、摘要或操作集合的内容。

### 2. 阅读与资料优先，装饰克制

页面视觉首先服务于扫描、比较和连续阅读。封面、人物头像与评分可以建立视觉锚点，但不以大面积 Banner、渐变、玻璃拟态或动画抢夺内容注意力。

**意味着：** 白或低噪声画布、有限表面层级、清晰文本对比和节制的阴影；圆角与阴影表达语义边界，而非成为全局风格。

### 3. 关系可见，路径可预测

一个条目同时关联人物、制作信息、章节、收藏状态、评论、讨论和相似条目。导航、页签、面包屑（如采用）与链接应持续告诉用户所在位置、可去何处、切换后会发生什么。

**意味着：** 全局导航、条目内导航、用户状态导航各有明确层级；当前态不只依赖颜色，并在移动端保留可理解的溢出与返回路径。

### 4. 社区表达被尊重且易于参与

日志、吐槽、评论与主题是产品核心内容，不是详情页末尾的附属模块。阅读回复层级、作者身份、时间、引用和操作需要稳定可扫描，同时发布、回复、收藏、评分等动作要获得清楚反馈。

**意味着：** 将评论/讨论的阅读模式与编辑模式分别设计；避免用浮层和强 CTA 打断长文本阅读。

### 5. 同一语义，同一套规则

“链接”“当前页签”“筛选项”“状态”“危险操作”不能仅因页面不同而任意变色或改变交互。允许页面组合不同，但基础 token、组件状态和可访问性规则应一致。

**意味着：** 先建立颜色、文字、空间、边框、焦点和状态 token，再建立 Link、Tabs、列表、分页、表单等基础组件；现有站点的实测值是兼容参照，不是新规范的自动答案。

### 6. 默认跨端、可访问，桌面效率不倒退

桌面端为资料密集型使用提供并列信息；移动端优先保证主任务、阅读和关键操作，而不是把 1200px 双栏机械缩小。键盘焦点、可见标签、文字对比、触控目标和状态反馈是基础质量。

**意味着：** 采用内容驱动断点；信息侧轨可下移或折叠；横向轨道提供明确提示；不把 hover 作为唯一反馈。

### 7. 宽屏用于并列比较，不制造空白

宽屏是资料浏览、编辑、比较条目和并读讨论的效率场景。布局应在合理上限内增加有意义的并列信息或更舒适的阅读列，而不是仅把固定宽度内容放在更大的留白中央。

**意味着：** 建立清楚的宽屏容器、阅读列与辅助列规则；长文维持可读行长，资料型列表可获得更宽的比较空间。

### 8. CJK 与西文是第一等排印场景

中文、日文、英文以及混排的标题、元数据、术语、数字和用户生成内容必须准确、稳定、易读。RTL 书写模式不在当前目标范围，但不能以错误字体回退、字符缺字或不可控的中西文间距为代价。

**意味着：** 字体 token 需要明确 CJK 与拉丁字符覆盖、跨平台回退、数字样式、行高和断行策略；应在不同系统语言环境的代表性样本中验证字形与字符集。

## 保留、升级、避免

| 保留                             | 升级                                     | 避免                                        |
| -------------------------------- | ---------------------------------------- | ------------------------------------------- |
| 高密度资料与社区文本并存         | 清楚的排印层级、可读行长与分区节奏       | 把所有内容改造成大图卡片流                  |
| 连续列表、交替行、表格式讨论     | 一致的悬停、焦点、选中与触控状态         | 仅用颜色表达当前、错误或可点击性            |
| 封面、评分、关系信息作为扫描锚点 | 移动端信息优先级和可折叠策略             | 为“现代”而使用大 Banner、自动轮播和过度动效 |
| 克制的白底与链接驱动信息架构     | 可访问的对比度、字号、点击区域和表单反馈 | 全站泛化阴影、圆角、玻璃效果或营销式 CTA    |
| 社区内容的长阅读流               | 回复层级、作者与时间信息的可扫描性       | 用频繁浮层中断阅读和讨论                    |

## 初步视觉性格（待确认）

- **关键词：** 编辑式、克制、亲和、资料感、轻盈而不轻佻。
- **色彩：** 保留粉色作为品牌锚点和当前态候选；可探索新的搭配色与视觉语言。蓝色主要承担链接语义。新系统需补足成功、警告、危险、信息及其对比度规则，不能只沿用历史字面色值。
- **排印：** CJK 与西文混排是硬性要求；字体字符集与跨语言字形必须经过验证。正文不应以“更小”换密度，密度主要由结构和间距调节。
- **形状：** 以直角或小圆角的连续内容面为默认；胶囊仅用于导航、分页、筛选等紧凑控制；需要被单独理解或操作的对象才使用更强表面边界。
- **动效：** 仅用于反馈、状态过渡和空间连续性；短、可关闭、遵从减少动态效果偏好。

## 体验北极星与衡量方式（待确认）

北极星体验：用户能在一次访问中，快速找到条目、判断是否感兴趣、理解相关信息，并自然地记录或参与讨论。

建议在试点页面验证：

1. 用户能否在不滚动或少量滚动后定位条目状态、评分、简介与下一步入口。
2. 用户能否快速区分条目资料、评论、讨论和吐槽，并回到对应区域。
3. 375px 与 768px 宽度下，核心阅读与操作是否无需横向滚动（明确的横向角色轨道等例外除外）。
4. 键盘用户是否始终看得到焦点，且所有关键操作具备非 hover 的反馈。

## 已确认的项目约束

| 主题             | 已确认决策                                                                                                                                       | 对设计系统的影响                                                                                  |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------- |
| 改版策略         | 渐进式现代化，不推倒重来；考虑既有用户习惯与适应成本。                                                                                           | 以现有信息架构和核心任务为兼容基线；通过试点逐步验证变化。                                        |
| 产品重点         | 保留 Wiki 内容密度，保留或提升编辑效率和可读性；优化宽屏、响应式与移动端交互反馈。                                                               | 同时定义桌面、宽屏与移动布局规则；优先建设高密度内容和编辑相关组件。                              |
| 品牌             | 保留主题粉色；主要用于品牌、导航当前态与填充操作，不作为普通正文链接或大面积纯文字强调。                                                         | 粉色进入品牌色候选；以高对比度深色阶承载填充控件，链接语义继续独立使用蓝色。                      |
| 覆盖范围         | 最终覆盖登录后的收藏、评分、编辑、发帖与通知；本轮尚未审计。                                                                                     | 这些流程进入后续审计和组件路线图，不以当前未登录页推断其交互细节。                                |
| 技术与兼容性     | React + SSR（SEO）；覆盖绝大多数现代需求，放弃 IE 等远古浏览器；组件库未定；需要基本可访问性与深色模式。                                         | Token 与组件需框架无关、支持 SSR；亮/暗主题同等覆盖并从开始定义可访问性要求。                     |
| 国际化排印       | 必须适配 CJK + 西文；字符集完整、不同语言环境字形正确；暂不考虑 RTL。优先使用系统字体；如需 Web Font，必须采用开放字体并处理加载造成的布局抖动。 | 字体、断行、字号、行高和数字排印需设为基础 token，并以多语言样本验收；Web Font 不作为 v0.1 前提。 |
| 信息密度与个性化 | 默认采用平衡密度；首发仅提供亮/暗主题切换。                                                                                                      | 默认正文 14px，紧凑数据行 13px；不在 v0.1 提供字号、密度或多皮肤设置。                            |

## 审核通过后的下一步

方向确认后，起草 `02-目标 Design Tokens v0.1`：先定义颜色语义（亮/暗）、排印（CJK + 西文）、空间、宽屏与响应式断点、层级、动效和可访问性基线，再从第一批基础组件开始，而不直接复制旧站 CSS。
