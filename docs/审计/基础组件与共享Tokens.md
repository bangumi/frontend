# 基础组件与共享 Design Tokens

- 采集来源：Chrome MCP 完成的条目、人物、发现、小组、日志、时间线、用户与目录页面审计，详见本目录的页面记录。
- 审计环境：以未登录的 `1920 x 893` 桌面视口为主；个别报告的浏览器窗口为 `1920 x 1032`，页面可用视口仍为 `1920 x 893`。以下仅汇总跨页重复出现或已触发的 `getComputedStyle` 证据。
- 使用边界：本文件是共享基线，不以单一页面的特殊容器、图片、业务控件或未触发状态推导全站规格。移动端、禁用、加载、错误和绝大多数键盘焦点态仍未审计。

## 共享布局基线

- **桌面壳层**：浏览、用户、小组和目录常用 `.mainWrapper` `1000px` 宽；条目页使用 `1200px` 壳层与 `1180px` 内容区。两种壳层均以居中、连续文档流组织页面。
- **双栏变体**：浏览页通常为 `700px` 主列 + `15px` 间距 + `280px` 侧栏；条目详情为约 `292px` 信息轨 + `875px` 主轨。侧栏通常只服务于页面上段，不等于固定或通用组件。
- **局部导航带**：`.subjectNav` 跨页面宽度、高 `41px`、表面 `#fbfbfb`，条目路由中为粘性带。内部 `.navTabs` 高 `39px`、`display: flex`、`gap: 5px`，标准内容宽度为 `1200px`。
- **内容流优先**：结果、章节、讨论、回复、时间线和文章摘要均以顺序阅读流为主；除已证实的角色轨道外，不以“横向滚动”类名推断实际滚动能力。
- **页脚**：`#footer` 在已审计页面中稳定为高 `196px` 的站点级链接与版权收束区，正文 400 / 12px / 18px、弱信息 `#aaa`；不属于任一业务卡片或分页组件。

## 常见 UI Pattern

1. **文本驱动的筛选与视图控制**：类型、职位、排序以及精简/列表/网格均以行内链接组织，筛选面通常为无阴影、直角浅面或透明面，而非 Select 或填充按钮。
2. **封面 + 元信息的高密度结果行**：竖版封面固定在左，标题、原名、评分、排名和辅助信息在右侧自然换行；行高由内容决定，避免强制等高卡片。
3. **交替行促进扫描**：透明奇数行与 `#f9f9f9` 偶数行跨浏览、收藏、目录和话题表复现；它是列表行状态，不是页面背景色。
4. **局部页签表达上下文**：条目、人物、用户页面都用文字页签切换上下文；当前态优先使用粉色文字，内容区在下方替换。时间线与目录的填充胶囊是专用筛选控件。
5. **信息轨与附属侧栏**：详情页使用封面/定义列表信息轨，浏览页和文章页可在首屏放置窄侧栏；它们是页面组合，不作为一概固定的通用 SidePanel。
6. **列表末端收束**：分页紧随连续内容，站点页脚再统一收束。不要在这两者之间插入无证据的浮层或 CTA 卡片。

## 组件一致性观察

- 系统以链接、留白、细分隔和连续内容流建立层级；默认不使用浮层卡片或外阴影。
- 阴影和圆角不是全局禁止项，而是语义特例：导航/分页的胶囊、评论面板与气泡、媒体缩略图、时间线筛选、目录分段控件均有实测例外。
- 原生搜索控件使用 Arial，和正文中文无衬线字体栈并不一致；重建时应保留其作为顶栏原生控件的边界，而不是静默套用正文排印。
- 颜色按组件语义复用，而非单一 Link token：`#0084b4` 是常规链接，`#02a3fb` 是已证实的标题/话题 hover，`#369cf8` 是 Tabs hover，`#f09199` 是选中/当前强调。
